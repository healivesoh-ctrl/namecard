# 다이음 다이렉트 — 친정엄마 산모신생아건강관리사 신청 시스템

가족·지인이 산모신생아건강관리사로 활동하는 **친정엄마** 서비스의 온라인 접수 시스템입니다.

> **다이음 다이렉트란** — 다이렉트 보험처럼 신청 과정을 전산화해 신청자가 직접 진행합니다.
> 중간 과정이 줄어드는 만큼 **수수료율이 가장 낮고**, 그만큼 **친정엄마 급여가 가장 높아집니다.**
> 신청 완료 후 근로계약 체결과 제공기록지 작성 등은 **오리지널 다이음과 동일한 시스템**을
> 사용하므로, 사용 편의는 그대로 두면서 시간과 비용만 줄입니다.
신청자는 접수 전에 필요 서류와 입력 항목을 확인하고, 접수 후 서류를 나눠서 올릴 수 있습니다.
다이음 관리자는 서류를 검토해 부족분을 반려하고, 진행 단계를 신청자에게 그대로 보여줍니다.

## 화면

| 경로 | 화면 | 내용 |
|---|---|---|
| `/` | 메인 | 이번 달 **친정엄마 소득**, 필요 서류 4종, 입력 항목, 진행 절차, `신청 접수하기` · `전화상담 신청하기` 버튼 |
| `/apply.html` | 신청서 작성 | 산모·도우미 정보 입력 → `접수하기(자동 승인)` 또는 `임시저장만 하기` |
| `/status.html` | 내 신청 조회 | 진행 단계, 반려 사유, 서류 업로드/삭제, 보완 후 재제출 |
| `/admin.html` | 다이음 관리자 | 신청 목록·상세, 서류 열람/승인/반려, 단계 변경, 카카오 친구추가 확인·이벤트 적용, 전화상담, 메인 화면 설정(서비스명·채널·소득), 알림톡 이력·템플릿, 구글 시트 연동 |

## 업무 흐름

```
[신청자] 신청서 작성 ──┬─ 임시저장(draft) ── 서류를 준비되는 대로 업로드 ── 접수하기 ─┐
                       └─ 바로 접수(자동 승인) ───────────────────────────────────┘
                                                                                    ↓
                                                                          접수완료(received)
                                                                                    ↓
[다이음 관리자] 서류 검토중(reviewing) ──┬── 부족 서류 지정 + 사유 → 보완요청(rejected)
                                        │            ↓
                                        │   [신청자] 반려 내용 확인 → 부족 서류만 추가 업로드 → 재제출
                                        │            └──────────────→ 접수완료로 복귀
                                        └── 최종확인 완료(confirmed)  ← 이후 수정·업로드 잠금
```

- **서류가 하나도 없어도 접수는 됩니다.** 접수 자체는 자동 승인이며, 서류는 나중에 채웁니다.
- **접수하지 않은 채 서류만 저장**해 둘 수 있습니다(`draft`). 다른 서류를 준비할 때까지 그대로 보관됩니다.
- 신청자는 `접수 → 검토 → 최종확인` 중 어느 단계인지 조회 페이지에서 항상 확인할 수 있습니다.

## 개인정보 동의

접수 화면에서 아래 4개 항목의 동의를 받고, **동의 시각과 약관 버전**(`CONSENT_VERSION`)을 함께 저장합니다.
문구가 바뀌면 버전을 올리세요 — 나중에 "무엇에 동의했는가"를 확인할 수 있어야 합니다.

| 항목 | 필수 | 내용 |
|---|---|---|
| 개인정보 수집·이용 | ✅ | 이름·연락처·출산예정일 등 신청 정보 |
| 민감정보(건강정보) 처리 | ✅ | 건강검진결과서, 예방접종 증명, 교육 수료증 |
| 카카오 알림톡 수신 및 채널 친구추가 | ✅ | 진행 안내 발송 |
| 이벤트·혜택 안내 수신 | — | 선택. 동의하지 않아도 접수·이용에 영향 없음 |

필수 항목에 동의하지 않으면 접수가 차단됩니다. **임시저장은 동의 없이도 가능**합니다.

> ⚠️ 동의 문구는 `server/db.py`의 `CONSENTS`에 초안으로 작성돼 있습니다.
> **오픈 전 법률 검토를 받으세요.** 개인정보 처리방침 게시와 보관기간 파기 절차는 별도로 필요합니다.

## 카카오채널 친구추가 (접수 필수)

모든 진행 안내가 알림톡으로만 발송되므로, **다이음 카카오채널 친구추가가 접수 필수 조건**입니다.

- 신청서에서 채널 친구추가 버튼 → 완료 체크를 해야 접수가 진행됩니다.
- **친구를 삭제하면 이벤트 혜택이 적용되지 않습니다.** 친구 상태는 이용 기간 동안 유지되어야 합니다.
- 관리자는 신청 상세에서 실제 친구 여부를 확인해 기록하고, 이벤트 적용/제외를 전환할 수 있습니다.
- 채널 주소와 안내 문구는 관리자 화면 `메인 화면 설정`에서 수정합니다.

## 알림톡 자동 발송

진행 단계가 바뀔 때마다 신청자에게 자동 발송됩니다.

| 시점 | 템플릿 | 담기는 내용 |
|---|---|---|
| 접수 완료(자동승인) | `received` | 접수번호, 아직 안 낸 서류, 친구 유지 안내 |
| 검토 시작 | `reviewing` | 검토중 안내 |
| 보완요청(반려) | `rejected` | **부족한 서류 목록 + 관리자 사유** |
| 최종확인 완료 | `confirmed` | 이후 오리지널 다이음에서 이어진다는 안내 |
| 전화상담 접수 | `consult` | 희망 시간 확인 |

### 실제 발송하려면

> **코드만으로는 발송되지 않습니다.** 알림톡은 카카오 비즈메시지 **발신프로필 등록**과
> **템플릿 사전 심사 승인**이 필요합니다.

1. 관리자 화면 `알림톡` 탭에서 템플릿 문구를 확인하고, 그대로 카카오에 등록해 심사받습니다.
2. 승인된 템플릿 ID를 `ALIMTALK_TEMPLATE_IDS`에 JSON으로 넣습니다.
3. 알림톡 업체(솔라피·알리고·NHN 등)를 붙입니다. 업체마다 API가 달라
   **웹훅 하나로 중계**하도록 만들었습니다 — `ALIMTALK_WEBHOOK_URL`에 중계 주소를 넣으면
   `{template_key, template_id, to, title, text}` 를 POST 합니다.
   업체 API를 직접 붙이려면 `notify.py`의 `_SENDERS`에 함수 하나만 추가하면 됩니다.

설정 전에는 `dryrun` 모드로 **발송하지 않고 문구만 기록**합니다. 관리자 화면에서
"무엇이 나갔을지"를 그대로 확인할 수 있어, 심사 전에 문구를 다듬기 좋습니다.
발송 실패는 이력에 남고 **재발송** 버튼으로 다시 보낼 수 있으며,
발송이 실패해도 접수·업로드 자체는 정상 처리됩니다.

## 친정엄마 소득 안내

최저시급 기준이나 매월 이벤트에 따라 금액이 바뀌면 관리자 화면 `친정엄마 소득 설정`에서 수정합니다.

## 구글 시트 · 드라이브 백업 (선택, 권장)

신청 정보는 **구글 시트**에, 업로드한 서류 원본은 **구글 드라이브**에 자동으로 복사됩니다.
서버 디스크가 초기화돼도 접수 내용과 서류가 남고, 관리자는 익숙한 시트에서 바로 필터링·정렬할 수 있습니다.

- SQLite는 그대로 주 저장소입니다. 시트/드라이브는 **사본**이며, 구글이 느리거나 죽어도
  접수·업로드 요청은 그대로 성공합니다(백그라운드 처리 + 3회 재시도).
- 신청 1건 = 시트 1행이며, 접수번호를 키로 **덮어쓰기**됩니다. 상태·부족서류·반려사유·
  제출/미제출 서류·드라이브 링크까지 한 행에 들어갑니다. 탭은 `신청`, `전화상담` 2개가 자동 생성됩니다.
- 관리자 화면 `구글 시트 연동` 탭에서 연동 상태·마지막 오류를 확인하고 `전체 동기화`를 실행할 수 있습니다.

### 설정 (약 5분)

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들고
   **Google Sheets API**와 **Google Drive API**를 사용 설정합니다.
2. `IAM 및 관리자 > 서비스 계정`에서 서비스 계정을 만들고, `키 > 새 키 만들기 > JSON`으로 키를 받습니다.
3. 구글 시트를 새로 만들고, 서비스 계정 이메일(`...@....iam.gserviceaccount.com`)을 **편집자**로 공유합니다.
   서류를 저장할 드라이브 폴더도 같은 이메일에 편집자로 공유합니다.
4. 서버에 환경변수를 넣습니다.

| 변수 | 설명 |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_JSON` | 2단계에서 받은 키 JSON **전체 내용**(또는 키 파일 경로) |
| `GSHEET_ID` | 시트 주소 `docs.google.com/spreadsheets/d/`**`이 부분`**`/edit` |
| `GDRIVE_FOLDER_ID` | 폴더 주소 `drive.google.com/drive/folders/`**`이 부분`** (생략하면 시트만 백업) |

5. 배포 후 관리자 화면 → `구글 시트 연동` → `전체 동기화`를 한 번 눌러 기존 데이터를 올립니다.

> 연동을 켜지 않아도 시스템은 그대로 동작합니다(연동 기능만 꺼진 상태).
> 더 간단한 대안으로 Apps Script 웹앱에 POST하는 방식도 있지만, 서류가 민감정보라
> 공개 엔드포인트를 두지 않는 서비스 계정 방식을 기본으로 했습니다.

## 실행

```bash
cd care
pip install -r requirements.txt
ADMIN_PASSWORD=원하는비밀번호 uvicorn server.app:app --reload --port 8000
```

`http://localhost:8000` 접속. 관리자 화면은 `/admin.html`.

### 환경변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `ADMIN_PASSWORD` | (없음) | 관리자 API 비밀번호. **설정하지 않으면 관리자 기능이 비활성화**됩니다 |
| `DATA_DIR` | `care/data` | SQLite DB와 업로드 서류 저장 경로 |
| `MAX_UPLOAD_MB` | `12` | 업로드 1건 최대 용량 |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | (없음) | 구글 백업용 서비스 계정 키. 없으면 연동 꺼짐 |
| `GSHEET_ID` | (없음) | 백업할 스프레드시트 ID |
| `GDRIVE_FOLDER_ID` | (없음) | 서류를 올릴 드라이브 폴더 ID. 없으면 시트만 백업 |
| `ALIMTALK_MODE` | `dryrun` | `dryrun`(문구만 기록) 또는 `webhook`(실제 발송) |
| `ALIMTALK_WEBHOOK_URL` | (없음) | 발송 중계 주소. `webhook` 모드에 필요 |
| `ALIMTALK_WEBHOOK_SECRET` | (없음) | 중계 요청에 붙일 `X-Webhook-Secret` 헤더 값 |
| `ALIMTALK_TEMPLATE_IDS` | (없음) | 카카오 승인 템플릿 ID. 예: `{"received":"TPL_01"}` |

Render 대시보드에서 `ADMIN_PASSWORD`를 입력한 뒤 배포하세요.

> Render **free 플랜은 영구 디스크를 제공하지 않아 재배포·재시작 시 서버의 데이터가 사라집니다.**
> 위 **구글 시트·드라이브 백업**을 켜두면 접수 내용과 서류 원본은 구글 쪽에 남으므로
> free 플랜에서도 자료를 잃지 않습니다. 다만 서버가 초기화되면 신청자의 조회 링크는
> 끊기므로, 운영 규모가 커지면 유료 플랜에서 디스크를 `/data`에 마운트하세요.

## 개인정보 취급 (중요)

이 시스템은 이름·연락처와 **건강검진결과서·예방접종 기록 등 민감정보**를 다룹니다.
운영 전에 아래를 반드시 확인하세요.

- `care/data/`는 `.gitignore`로 커밋이 차단돼 있습니다. 업로드 서류를 저장소에 올리지 마세요.
- 반드시 **HTTPS**로 서비스하세요. 조회 링크에 열람 토큰이 포함됩니다.
- 조회 링크는 접수번호 + 산모 연락처로 다시 발급받을 수 있습니다. 링크 자체를 공유하지 않도록 안내합니다.
- 서류 응답에는 `Cache-Control: no-store`가 설정돼 중간 캐시에 남지 않습니다.
- 구글 백업을 켜면 서류 원본이 **회사 구글 드라이브에도 저장**됩니다. 폴더 공유 범위를 담당자로 한정하고,
  서비스 계정 키(`GOOGLE_SERVICE_ACCOUNT_JSON`)는 저장소가 아닌 서버 환경변수로만 관리하세요.
- 동의 수집 화면은 구현돼 있으나 **문구는 초안이며 법률 검토가 필요**합니다.
  개인정보 처리방침 게시와 **보관기간 경과 서류 자동 파기**는 아직 없습니다.
